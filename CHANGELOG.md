# Changelog

## 0.2.0-dev.1 — 2026-10-20

Development preview of the accepted data and local-investigation foundation.
Problem-specific AI investigations are still under development for 0.2.0;
existing AI settings, compact outbound evidence and default AI-off behavior remain.

- Preserve existing observations, settings, analyses and usage reservations through
  versioned SQLite migrations, with consistent private rollback snapshots.
- Retain bounded sanitized automation structure and step evidence, separating
  whole-run outcomes, continued errors, unknown timing and incomplete coverage.
- Add prioritized local cases, incident dossiers, manual checks and local
  known/expected/snoozed attention states without altering Home Assistant.
- Compare runs against their retained configuration, inspect typed dependencies
  and structural changes, and search paginated observation/history records.
- Bound landing-page work, static findings, trace reads and retained step details;
  keep missing evidence and source limits visible.

Upgrade uses the existing repository URL, app slug and private data volume.
Keep Supervisor's previous-version backup enabled. Container, publication and
live-update evidence are recorded separately in `docs/VALIDATION.md`.

## 0.1.0 — 2026-10-19

- Read-only Home Assistant device/entity, automation, Repairs and log observation.
- Persistent incidents, availability intervals, execution summaries and exceptions.
- Responsive Ingress dashboard and per-automation details.
- Optional Anthropic/OpenAI analyses with typed minimized evidence, validated
  diagnoses, technical failover, backoff and separately authorized budget failover.
- Persistent token/cost estimates and uncertain-request reservations.
- Explicit Ingress user authorization and credential redaction.
- Light white interface with Vision red/gold branding, green status accents,
  visible keyboard focus and responsive layouts.

Live Supervisor/Ingress, monitoring, native trace comparison and restart-history
verification passed. Installation evidence, source provenance, publication status
and known limits are recorded in `docs/VALIDATION.md`.
